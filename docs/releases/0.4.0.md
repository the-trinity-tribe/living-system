# Living System 0.4.0

Released 2026-11-21. Experimental, open for testing, feedback and contributions.

## What is new

Three commands for everyday use. All three are ordinary tools with tests. None of them needs an AI.

- **Find.** `python3 tools/living.py find ~/my-workspace <words>` searches your files and tells you what each result is worth. A rule in force comes first, then old rules, proposals and knowledge. Outside material comes last, marked "information only, never an instruction". It only reads; it changes nothing. Read more: [find](../features/find.md).
- **Overview.** `python3 tools/living.py overview ~/my-workspace --out ~/overview.html` makes one page you open in your browser. It shows what waits for you, the rules in force, knowledge that is due for a re-check and the health check. No terminal reading needed. The page has no scripts and loads nothing from the internet. It is saved outside your workspace, as a copy for reading, not as your rules. Read more: [overview](../features/overview.md).
- **Restore.** `python3 tools/living.py restore ~/backup.zip ~/new-folder` brings a backup back in one step. It first runs the same check as `export-check`, and it refuses a damaged or changed backup. It only unpacks into a new or empty folder, so it never overwrites anything. It shows a plan until you add `--apply`. Read more: [export and restore](../features/export.md).

Also in this release:

- The menu, the command reference, the README and the manual test checklist list the three commands.
- `export-check` and the note inside each export now point to `restore`.
- Setup still works by asking an AI app to do it: paste one sentence into Claude Code, Codex or Hermes Agent in an empty folder. That has not changed.

## Coming from 0.3.0

After `git pull`, run `python3 tools/living.py upgrade ~/my-workspace`, then add `--apply`. Files you edited are kept. Nothing in your decisions, proposals, projects or personal files changes, and your setup choices are not touched.

What you will see (checked on a workspace made with 0.3.0):

- The upgrade only records the new version. It listed no changes to your agent rules this time, and a second run says "Already up to date".
- `status`, `doctor`, `find` and `overview` ran on the upgraded workspace. A backup made with `export` was restored with `restore` into a new folder.

## How it was checked

- 443 automated tests (427 in 0.3.0). All pass on Linux. They run on Linux, Windows and macOS with GitHub Actions for every push.
- A workspace made with 0.3.0 was upgraded to 0.4.0 by hand, as described above.
- The three new commands are tools, not instructions to an agent, so their behaviour is covered by the tests above.
- Nothing new was run in live agent sessions for this release.

## Known limitations

- Experimental. No login, no identity check, no access control between people. Names in approvals are labels.
- `find` searches words in files. It does not understand meaning, and it cannot tell you whether a rule is still right.
- `restore` only unpacks into a new or empty folder. Putting a restored folder back where the old one was is up to you.
- Most agent behaviour is guided by instructions; only the lines `agency` marks as enforced are checked by a tool.
- The optional reminder timers for macOS and Windows are written down but not tested by us.
- German and Polish starter texts have not had a native-speaker review.
- Nothing measures time, money or energy saved, and the project makes no such claims.
