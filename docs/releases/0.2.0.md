# Living System 0.2.0

Released 2026-10-24. Experimental, open for testing, feedback and contributions.

## What it is

Living System is a governance layer for working with AI agents, built from plain files. Your rules, knowledge and working context live as Markdown on your own computer. Claude Code and Codex read them at the start of every session. An agent can propose a change to what you decided; only a human review turns it into a rule, and the old rule stays as history. No server, no account, no vendor lock-in: Python standard library and Markdown.

## Highlights

- **Agents propose, people decide.** Proposals of four kinds (new rule, exception, replacement, retirement), a deterministic review tool that refuses stale or invalid changes, a chained review record that shows anything changed after approval, and a write guard that blocks agents from editing rules, approving things or writing secrets (Claude Code; Codex once you trust its hooks).
- **Agency, honestly labelled.** `living.py agency` lists who may do what and marks each line as enforced by a tool or only an instruction. Delegation levels (observe, recommend, draft, act with approval, bounded) are granted per kind of work, with evidence, and withdrawn in one step. Publishing, sending, spending, deleting, signing and changing rules always keep a human yes.
- **Your own terms.** A personal work agreement the agent reads every session, including when to challenge you and what time saved is for.
- **Teams.** A shared company workspace with private personal ones; role knowledge is handed on after a check (contact details and secrets are refused; names need a human eye), someone else accepts it, and the next person gets a gentle onboarding path.
- **Calm by design.** Status, catch-up after time away, parking ideas with a decision and a date, focus mode, a tidy-up pass, and an atlas of what relies on each rule. No surveillance, no scores.
- **Safety for shared material.** Outside e-mails and documents are treated as information, never instructions, and scanned for hidden instructions and secrets.
- **Learning, not just doing.** Coach mode, practice questions on your own rules, and a printable handbook for working without AI.
- **Eleven optional modules,** from weekly updates and meeting notes to a careful-run workflow with safe pause and resume, research review, client intake and small experiments.

## Try it in five minutes

```sh
git clone https://github.com/the-trinity-tribe/living-system.git
cd living-system
python3 tools/living.py init ~/my-workspace --profile professional --language en
python3 tools/living.py status ~/my-workspace
```

Then open `~/my-workspace` in Claude Code or Codex. Or open the repository itself and say *"Read INSTALL.md and set up my workspace."* On Windows, type `py` instead of `python3`. The [testing guide](../../TESTING.md) has a 30-minute path.

## Coming from a 0.2.0 preview

After `git pull`, run `python3 tools/living.py upgrade ~/my-workspace` and then add `--apply`. Files you edited are kept; nothing in your decisions, proposals, projects or personal files is changed. Two agent rules changed since preview 2 (checking your work agreement before producing work; not counting workspace questions as repeated work).

## How it was checked

- 407 automated tests on Linux, Windows and macOS with Python 3.10 and 3.13.
- Seven independent code reviews (Codex) found 144 defects; all were fixed, each with a test.
- 13 everyday scenarios run live in both Claude Code and Codex: all 26 runs pass ([results](../../demo/WALKTHROUGH.md)).

## Known limitations

- Experimental. No login, no identity check, no access control between people; names in approvals are labels.
- Most agent behaviour is guided by instructions; only the lines `agency` marks as enforced are checked by a tool.
- The Codex write guard needs you to trust its hooks once, and has not yet been exercised in a live test.
- German and Polish starter texts have not had a native-speaker review.
- Nothing measures time, money or energy saved, and the project makes no such claims.
