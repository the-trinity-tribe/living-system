# Living System 0.3.0

Released 2026-10-26. Experimental, open for testing, feedback and contributions.

## What is new

**How the yes works day to day.** Until now the docs did not say when you look at what your agent proposes. Now you choose, and the docs and the tool say the same thing.

- **Two ways to say yes.** *Batch* (the default): your agent writes a proposal, tells you in one line and carries on; you go through what is waiting in a short pass. *Ask now*: your agent asks you right away.
- **A review rhythm.** New workspaces start with *weekly*. You can choose daily, monthly, a number of days, or off. When something is waiting and your rhythm has passed, `status` shows one line, and `living.py nudge` says it once a day at most. If nothing is waiting, you hear nothing. Nothing runs in the background and nothing is tracked beyond a few dates in your settings file.
- **Who else may approve.** Setup now asks. The answer becomes a rule you approve yourself, starting with `Approvers:`. Until you approve it, only you approve. `status` and `agency` list it.
- **Seven setup questions**, up from five: the two new ones are who else may approve, and the review mode and rhythm.
- **Honest labels.** Only the review command creates or changes a rule, and a tool enforces that. Batch or ask-now, the once-a-day reminder and who else may approve are instructions to your agent. `living.py agency` marks each line.

Read more: [the review loop](../features/review-rhythm.md), and the README section "How the yes works day to day".

**Also in this release**

- A new headline for the whole project: "Your context, your rules, any AI agent".
- Start in one sentence: paste one sentence into your agent in an empty folder and it downloads Living System and starts the guided setup.
- The README is easier to read, especially on phones, and shows everything Living System offers in benefit-led groups. A new section "Made for how you work" covers students, professionals, employees and managers.
- Clearer on which agents work: Claude Code, Codex, Hermes Agent, other agents that read `AGENTS.md`, and local models, with what was checked and what was not.
- Live checks: the Codex write guard blocked a direct edit of an approved rule, and Hermes Agent answered from the workspace rules and wrote a valid proposal instead of editing.
- Credits now name everyone whose work inspired Living System, and say that none of them built or endorsed it.

## Coming from 0.2.0

After `git pull`, run `python3 tools/living.py upgrade ~/my-workspace`, then add `--apply`. Files you edited are kept. Nothing in your decisions, proposals, projects or personal files changes, and your setup choices are not touched.

What you will see (checked on a 0.2.0 workspace):

- **You stay silent about reviews until you set a rhythm.** Your existing workspace has no rhythm, so `status` and `nudge` print nothing about reviews. Turn it on with `python3 tools/living.py review-rhythm ~/my-workspace --every weekly`.
- **Your agent rules change.** The upgrade adds a new section (16) to the workspace `AGENTS.md` and a small change to the `tend` skill. By default your agent now works in batch mode: it tells you about a new proposal in one line instead of stopping to ask. If you prefer to be asked right away, run `review-rhythm ~/my-workspace --mode ask-now`.
- Existing decisions, review records and the write guard work as before.

## How it was checked

- 427 automated tests (407 in 0.2.0), run on Linux, Windows and macOS with GitHub Actions for every push; the checks for the review loop commit passed.
- The release check (`tools/release_check.py`) and the demo workspace check pass.
- A 0.2.0 workspace was upgraded to 0.3.0 by hand: the upgrade changed only the agent rules, `status` and `nudge` stayed silent, and `doctor` and the review check passed.
- The new agent behaviour (batch or ask-now, the once-a-day reminder, checking with the owner about an approver) is an instruction and has **not** been run in live sessions yet.

## Known limitations

- Experimental. No login, no identity check, no access control between people. Names in approvals are labels, and "who else may approve" cannot be checked by a tool.
- The optional reminder timers for macOS and Windows are written down but not tested by us. The Linux recipe was tested with a stand-in notifier.
- Most agent behaviour is guided by instructions; only the lines `agency` marks as enforced are checked by a tool.
- German and Polish starter texts have not had a native-speaker review.
- Nothing measures time, money or energy saved, and the project makes no such claims.
