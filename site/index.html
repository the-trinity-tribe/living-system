    Living System

    One set of plain files that you and your AI agents share. Agents can suggest changes to what you decided. They never quietly replace it.

    Invented and tested by Adrianna Mamczarz inside The Trinity Tribe. Free and open source (MPL-2.0).

    What the status chips mean

      You keep explaining the same rule

      You tell one AI who approves client work. A week later you tell a second one. Then a third, in slightly different words. Now they disagree, and you are the one who remembers which is right.

      Chat A (illustration)"Maya signs off on client work."
      Chat B (illustration)"Leo can approve the routine stuff."
      Chat C (illustration)"I'm not sure who approves. Ask the team?"
      • Knowledge is scattered. It lives in chats, documents and people's heads.
      • Founders become the bottleneck. Every "who decides this?" goes to one person.
      • Employees rebuild context. Each new task starts with "what do I need to know first?"

      What changes: the rule is written down once, in a plain file. Every person and every AI agent reads the same file. When something new comes up, it becomes a suggestion that a human approves or rejects.

      A web chat can explain. It can't keep your files.

      A chat in your browser is good for explaining an idea or drafting a paragraph. It cannot open the folder on your computer, read your approved decisions, or update a file when something changes.

      Agents such as Claude Code and Codex can. They work inside a folder, within the permissions you give them. That is what makes a shared, durable memory possible.

      How it works: what "within permissions" means

      You choose which folder the agent opens and what it may read or change. The agent tool asks for your approval in the ways its own settings allow. Those settings differ between tools, so check them before you put real material in a folder (see chapter 10).

      Read more: Which AI tool you need, and what the permissions mean

      Ask once. Get the one approved answer.

      The agent does not read everything. It follows a short route to the one file that holds the current rule, and it says where the answer came from.

      How it works: the order of trust

      The repository ranks sources: (1) what the human tells the agent now, (2) approved canonical files, (3) project files, (4) background notes, (5) the agent's own guess. A lower source never overrides a higher one. A proposal is not on the list at all.

      A decision is current only if no other approved decision names it in supersedes:. The command python3 -B tools/review.py current lists the current ones. Source: AGENTS.md section 2.

      Read more: Decisions and proposals

      New information becomes a proposal, not a rewrite

      Someone writes in a meeting note that a rule has changed. The agent does not act on it. It keeps following the approved decision, writes down the suggestion, and waits for a human.

      Your first rule takes two minutes. Right after setup, say “Help me make my first decision from my setup answers.” The agent turns a rule you mentioned, such as “nothing goes to a client without my OK”, into a proposal, asks you about the wording, and you approve it yourself. Claude Code and Codex both did this correctly in a recorded test run.

      How it works: what the review tool does

      The review command records the outcome on the proposal. Approving creates one new decision file with supersedes: and source_proposal: and never edits the old file. It refuses if the target changed since the proposal was written, or if the proposed text is not exactly one quoted block.

      A proposal can add a first rule, add an exception, replace a rule completely, or retire it so no rule applies. In every case the old decision file stays unchanged as history.

      The name given with --by is a label. It is not a login and it is not checked.

      Add only what you need

      Five optional modules to start: a weekly update, meeting notes that turn remarks into proposals, lessons the agent may suggest but only you approve, a knowledge inbox that keeps sources and reminds you to re-check old facts, and a second check where a fresh agent reviews important work before you decide. Every command shows its plan first and writes nothing until you say yes. Removing a module keeps the files you edited and never touches your decisions.

      Suggestions are an instruction to the agent: it mentions a fitting module when the same need keeps coming up. Nothing watches or counts your work.

      Check it on your own work

      The value check takes about ten minutes and uses five questions about your own work. You ask the same five questions twice: once in a fresh web chat, and once to an agent working in your workspace. Then you score each answer yourself.

      This measures context continuity: does the answer match what is actually true for you? It does not measure money, time saved or quality of writing.

      Example questions

      These five are examples of the kind of question to ask. Replace them with questions where you know the true answer.

      1. What are my main goals right now?
      2. Who decides this, and where is that written down?
      3. What did we decide last time about this, and why?
      4. What is waiting for a decision?
      5. What should an assistant never do without asking me?

      Score your answers

      For each answer choose: Right, Wrong, Made up (sounded sure, but invented), or Don't know (it said so honestly). Nothing leaves this page.

      Workflows you don't have to design from scratch

      A repeatable task becomes a small folder per stage. Each stage reads only what it needs and leaves a plain file for the next one. Here is a hand-written example for preparing something that needs sign-off. Select a stage.

      workflow/

      Gather

      Collect only the facts the task needs, from approved files. Write down which files were used.

      Draft

      Write the draft from what was gathered. Anything uncertain is marked as uncertain, not smoothed over.

      Approval check

      Look up which current decision says who must approve this. Stop, and hand the draft to that person.

      Credit: the idea of using folders and plain files as the structure of a workflow comes from the Interpretable Context Methodology (ICM) by Jake Van Clief and David McDermott. Living System reimplements the idea in its own way. No endorsement by the ICM authors is implied.

      Workflow generator

      Ask your agent for a workflow, for example "a workflow for planning a launch post". It suggests the stages and shows the plan. After your yes it creates the stage-by-stage folders, with every part still to write clearly marked, and fills them in with you.

      Same files, Claude Code or Codex

      The knowledge lives in the files, not in one vendor's tool. Each agent gets a thin adapter file that points it to the same starting place. The tools still differ: in their settings, permission prompts and how they phrase answers, so results can differ too.

      What it is not

      • No login. Nobody signs in.
      • No access control. Anyone who can open the folder can read and change the files.
      • No identity check. A name in approved_by or --by is a label someone typed, not proof of who they are.
      • No compliance guarantees. It is not a security boundary and makes no data-protection claims.
      • Agent rules are instructions, not enforcement. An agent is asked to follow them. Nothing forces it to.
      • Not a hosted product. It is plain files and a small Python tool on your computer.

      The example organisation is a demonstration, not a recommended setup for real client or personal data. Review any material before you put it in an AI agent's context.

      Try it

      You need Git and Python 3.10 or newer. No accounts and no extra Python packages. On Windows, type py where the commands say python3.

      1. Get the code

      git clone https://github.com/the-trinity-tribe/living-system.git

      2. Create your own workspace

      Pick your profile (student, professional, employee or manager) and language. Run this from the living-system folder.

      python3 -B tools/living.py init ~/my-workspace --profile manager --language en

      3. Open it in an agent

      Open ~/my-workspace in Claude Code or Codex and ask the agent to start at AGENTS.md. Then say “Help me make my first decision from my setup answers.” Prefer a guided setup? Open the living-system folder instead and say “Read INSTALL.md and set up my workspace.”

      4. See what needs your attention

      Any time, this lists proposals waiting for your review, drafts you have not approved and where the last session stopped. It changes nothing. When a newer Living System comes out, upgrade updates only the files you never changed.

      python3 -B tools/living.py status ~/my-workspace

      About

      Adrianna Mamczarz is a product designer and brand strategist moving into Human–AI systems design. She invented and tested Living System's features and structure in her own practice, inside The Trinity Tribe.

      AI assisted with implementation. Design decisions, review and acceptance stayed human-led (from the README).

      Influences

      • Jake Van Clief (with David McDermott, ICM) — letting folders and plain files guide AI one small step at a time, so each step is easy to check.
      • David Shapiro — asking what AI should be for (less suffering, more prosperity, more understanding), and which work should stay human.
      • Jacque Fresco — designing whole systems around real human needs and the planet's limits, rather than around tools.
